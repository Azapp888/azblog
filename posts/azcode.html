AzCode:让模型直接操作你自己的设备

这是我最近做得最投入的一个项目,叫 AzCode。一句话说清楚它:你用自己的话描述一件想做的事,模型做决策,然后直接操作你现在用的这台设备去把事做完。不是问答,是让模型真的动手。

为什么想做它

之前我用过不少"AI 助手",但大多数只能聊天、只能给建议,最后一步还是要我自己去点。我手边有手机、有电脑、有一台常年开着的 Linux 服务器,很多重复操作其实很适合交出去——比如"打开设置看看 Android 版本""把这批文件按日期整理一下"。于是我想:能不能让模型自己把手也伸过去?

关键点是:所有操作都发生在本机,模型只负责决策和调用工具,具体的动作由设备自己的能力完成。这样我不用把设备交给某个云端服务,数据也不出本机。

三端,两个形态

AzCode 不是单个 App,而是一组跑在不同平台上的独立助手,功能对等,共用一个命名约定和核心机制。按平台分了三端:

  • Android(Kotlin 原生):通过无障碍 / Shizuku / Root 直接操作手机,内置聊天界面、多模型提供商、完整 Markdown、技能与插件管理。
  • Windows(.NET 8 / WPF):用 UI Automation 读屏、模拟键鼠、执行 PowerShell,直接控制这台电脑。
  • Linux(Python):同一入口按桌面环境自动选择图形界面或命令行。

同一个平台还有两个形态:有图形环境时用的是带界面的 magic,没有图形环境或者在终端里更顺手时用命令行的 Listen。两个形态共用同一套 Agent 核心、配置和插件,所以行为是一致的。Linux 端装完是这样用的:

curl -fsSL https://raw.githubusercontent.com/Azapp888/AzCode/260912-feat-linux-native/linux/install.sh | bash
listen chat          # 命令行
magic                # 图形界面

最花心思的地方:让缓存命中

做多轮任务时我才发现,真正影响成本和延迟的不是模型本身,而是"缓存有没有命中"。大模型提供商按"消息前缀逐字节一致"来复用缓存,只要前面任何一个字节变了,那一处之后的缓存就全部失效,得多花钱也多等时间。

所以 AzCode 把系统提示拆成了两段:

  • 稳定前缀:第 0 条 system,只放我长期设置的人设,字节永久不变。
  • 运行时上下文:技能、记忆、插件提示单独成一条 system 消息。内容没变就不重复插入,变了就追加到历史末尾,绝不回头改写前缀。
  • 工具定义的顺序固定,不随条件增删。

这套机制是我从 deepseek-harness 移植过来的。效果很直接:多轮任务能持续命中前缀缓存,又便宜又跟手。支持在任意位置追加 system 消息的模型(比如 deepseek-flash)会把最新那条当成完整系统提示,旧的自然被取代。

插件市场

AzCode 带一个很小的插件市场,最初是考虑到不同任务需要不同的约束:

  • 内置 ponytail:第一次启动就写入一条"拒绝过度设计"的技能,约束 Agent 只做最小必要的改动。这条对我挺重要——模型很容易给你加一堆用不上的东西。
  • 扫描热门插件:按关键词搜 GitHub 上 star 较多的 Agent 技能仓库,一键安装里面的 SKILL.md。
  • Agent 自助:模型自己也能通过工具去搜索、安装、启停、删除插件。

整体架构

magic / Listen(各端 UI)
        │
        ▼
   Agent 决策循环 ── PromptCache(稳定前缀 + 运行时上下文追加)
        │
        ├── 大模型 chat/completions(OpenAI 兼容 function calling)
        └── 设备能力
              ├── Android:无障碍 / Shizuku / Root
              ├── Windows:UI Automation / SendInput / PowerShell
              └── Linux:bash / 文件 / xdotool / 截图

结构其实很朴素:UI 只是外壳,中间是决策循环,底下是各端的"手"。换平台要动的只是最下面那一层,上面全部复用。

现在和边界

它还很年轻,仓库总共也就几次提交,功能对等但也只是"能用"。目前我主要在 Android 上自己用来处理一些重复操作,Windows 和 Linux 端跟着对齐。下一步想做的,是把权限边界收得更细一点——毕竟让模型直接操作设备,安全永远要排在功能前面。
