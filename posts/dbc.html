dbc:用 Kotlin 原生写一个 DeepSeek 安卓客户端

dbc 是我用 Kotlin 原生写的 DeepSeek 安卓客户端。它只做一件事:用你自己的 API Key 直连 DeepSeek 官方 API,在手机上跟模型对话。我用的是 Android 原生的 Kotlin + Jetpack Compose,没有套一层 WebView,也没有内置任何密钥。

为什么不用 WebView 套壳

套壳最快,但体验是假的:流式输出会卡,键盘和输入框对不齐,返回手势也别扭。我想试试"真的是个安卓 App"是什么感觉——原生渲染每一条消息、原生处理流式输出的逐字追加。写下来确实比套壳累得多,但那种跟手的感觉值得。

都做了哪些功能

  • 深度思考(思维链):把模型的推理过程展示出来,不是只给最终答案。
  • 自定义思考深度:按需调节推理档位,简单问题不必浪费算力。
  • 联网搜索:让模型结合实时信息回答。
  • 技能挂载:可插拔的提示词技能系统,不同场景挂不同技能。
  • 历史会话:多会话管理,本地持久化。
  • 图片识别:拍照或选图后做多模态问答。
  • 流式输出:逐字返回,可以随时中断。

技术栈

Kotlin + Jetpack Compose(Material 3),协程与 Flow 处理异步和流式,网络用 OkHttp + Kotlinx Serialization,本地存储用 Room / DataStore,构建脚本是 Gradle Kotlin DSL。这一套基本都是现在写安卓的标配,顺手也把协程和 Flow 的用法练熟了不少。

API Key 只在设备上

这是我很在意的一点:App 里自己填 DeepSeek API Key,只保存在设备本地的 DataStore 里,不上传到任何第三方服务器,源码里也不含任何内置密钥。客户端这种东西,一旦把 Key 塞进包里或者过一遍自家服务器,风险就说不清了。让用户自己带 Key、Key 只留在本机,是最干净的做法。

怎么构建

./gradlew assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk

用 Android Studio 打开目录、等 Gradle 同步完直接运行也行。需要较新版本的 Android Studio、JDK 17 和 Android SDK 35+,细节都写在仓库的 BUILD.md 里,踩过的坑记在 FIXES.md。

写在最后

这是个人自用的客户端,和深度求索公司没有隶属关系。仓库里移除了构建产物、Gradle 缓存和截图等媒体文件,代码是完整的。对我这个平时主要写 Web 的人来说,完整做一遍安卓原生 App 是次不小的挑战,也让我明白:原生和套壳的差距,最后都体现在那些小的、跟手的地方。
