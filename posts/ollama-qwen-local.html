在自己服务器上跑 Qwen:一次真实的本地大模型部署

先交代背景:我有一台自己的 VPS,平时跑着几个小项目。前阵子想把开源大模型也搬上去,给自己写个小助手用。整件事花了我一个周末,中间踩的坑比想的还多。这篇把过程记下来,也给同样想折腾的人一个参考。

为什么是自己部署,而不是直接用现成的 API

原因很朴素:便宜,而且好玩。现成的 API 按量收费,我这种用法一个月没几个请求,付钱划不来。更重要的是,把模型装在自己机器上、看着它真的跑起来,那种感觉和"调一个接口"完全不一样。

装 Ollama

本地跑开源模型最省事的入口是 Ollama,一条命令装好:

curl -fsSL https://ollama.com/install.sh | sh

装完以后 Ollama 会在本地监听一个端口,对外提供类似 OpenAI 的接口。后面所有应用都直接打这个端口,不用关心模型本身。

选模型:先被磁盘教育了一课

我第一次直接拉了一个挺大的 Qwen 模型,结果下载进度条走完的时候,磁盘也差不多满了。这是我的失误:装之前应该先 df -h 看一眼剩余空间。模型文件动辄几个 G,加上日志和缓存,VPS 那点磁盘真的经不起造。

后来我换成了一个更小的量化版本,速度反而更快,日常对话完全够用。一个心得是:先跑最小的能用的,不够再往上加,别一上来就堆参数。

写成接口给自己用

模型跑起来之后,我写了一个很小的 Flask 服务,把 Ollama 的接口包一层,加上自己的逻辑(比如上下文裁剪、简单限流),这样我的小工具就能统一调它,不用各自处理细节。

import requests

def ask(prompt: str) -> str:
    r = requests.post(
        "http://127.0.0.1:11434/api/chat",
        json={"model": "qwen", "messages": [{"role": "user", "content": prompt}]},
        timeout=120,
    )
    return r.json()["message"]["content"]

就这么点东西,但它是整个系统里我最满意的部分:模型换哪个版本,只需要改一个字符串,上层代码一行不动。

几个真实的坑

  • 磁盘:装之前一定先看空间,模型文件比想象的大。
  • 内存:模型加载时会瞬间吃掉一大块内存,小内存的机器容易直接被 OOM 杀掉。
  • 超时:大一点的模型第一次回复可能十几秒,客户端超时时间给小了会误以为挂了。
  • 安全:Ollama 默认只听本机回环地址,这是对的。别图方便把它直接暴露到公网。

最后

整个部署到现在一直稳定跑着,我的几个小工具都靠它。它不是什么高深的架构,就是"自己的服务器 + 一个开源模型 + 一层薄接口"。但对我来说,能完全自己控制的东西,用起来就是踏实。
