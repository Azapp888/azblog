PersonaBot：让每个 QQ 号都有自己的性格与记忆

我一直想做的不是「一个能聊天的机器人」，而是一个有角色、会记事、能长期陪着聊的 QQ 号。于是有了 PersonaBot——一个轻量的角色扮演 QQ Bot 管理系统：每个 Bot 绑定一个角色人格，每次对话都以那个角色的身份运行，多个 Bot 各自独立跑在自己的网关上。

为什么不是「一个 Bot + 一堆提示词」

最早我也是把所有人的对话塞进同一个机器人，人格写在系统提示里。很快就崩了：两个人同时在聊，记忆串味；想换一个角色，得把提示词整段重写；某个角色想用不同的模型、不同的绘画配置、不同的主动消息节奏，只能靠开关硬撑。

所以 PersonaBot 把「Bot」和「角色（Persona）」拆成了两层：Bot 只管 QQ 侧的凭据与连接，角色管人格提示词、技能插件、命令池、绘画配置和模型选择。一个角色可以绑给多个 Bot，一个 Bot 也只能绑一个角色，改哪个都不影响另一个。

记忆是分层写下来的

聊天越久，上下文越塞不下——这是所有陪聊类项目都会撞到的墙。我的做法是分层总结，而不是无脑截断：

  • 滚动摘要 + 滑动窗口：老对话压成摘要放在消息末尾，窗口内保留原文，近期的语气和细节不丢。
  • 核心记忆 + 增量注入：把稳定的事实（称呼、习惯、重要经历）单独存，只在必要时注入，不占每轮额度。
  • 时间感知：日记忆 → 三日记忆 → 两周精简 → 月记忆，定时任务一层层往下压，半夜跑，不打扰对话。
  • Markdown 落盘：MEMORY.md、USER.md、persona-state.md 可以直接打开看、手动改；改过的文件默认不再被自动覆盖，想继续让 AI 追加，得显式打开开关，只往文件末尾的追加区写。

这一点我坚持得比较死：记忆必须是我能看懂的文本，而不是一坨埋在数据库里、只有模型自己知道的东西。

缓存命中率才是成本

跑了一段时间我才意识到，多轮对话真正的开销不在模型单价，而在「缓存有没有命中」。所以整条管线都围着前缀复用设计：

  • 角色人格定义放最前，字节级不变；时间、记忆、状态这些动态内容全放末尾。
  • 同一用户与角色始终用同一个会话，历史只追加，不重写，也不回头重新总结更早的轮次。
  • 自动压缩时，摘要追加到消息末尾，前面那段前缀依然是原来的字节。
  • 统计页直接给出命中率：cacheRead / (input + cacheRead + cacheWrite)，好不好一眼就知道。

不会把「走神了」写进聊天记录

模型调不通的时候，最容易犯的错是把失败提示当成角色的回复存进会话。一旦存进去，它就成了下一轮的历史前缀，模型会顺着这句「我走神了」继续聊，还会被记忆总结当成事实收进去，越滚越脏。

现在的做法是：请求失败静默重试，不写会话、不进记忆；同时加了一道回复质量闸，明显是模板话、空话或者出错的回复会被拦下。管理端还多了会话管理，可以精确删某条消息或从某条往后清空，顺手清掉被污染的内容。

模型、读图与搜索都在后台配

「模型管理」是以提供商卡片为首页的：名称、Base URL、密钥统一维护，级联到下面所有模型；模型本身只存 modelId、显示名、温度、最大 token、是否读图。支持检测上游 /models 拉取可用模型、批量加入，品牌图标是内置的真实 SVG，不是 emoji 凑的。

多模态这块以前很别扭：主模型不支持读图，收到图片就只能干瞪眼。现在会自动判断，转给视觉副模型转述后再重试一次，用户那边无感。搜索也是按 Bot 独立开关，由模型自己决定什么时候去查。

还有一层是我自己被坑出来的——「完整日志体系」：消息日志记「说了什么」，运行日志记「做了什么、耗时多少、为什么失败」，能筛选、能分页、能导成 JSON / Markdown。出问题的时候，先看日志再猜，比凭感觉改代码快得多。

安全上不敢省的地方

这类项目手里握着的东西太多了：QQ 的 ClientSecret、一堆模型 API Key、GitHub Token。所以：

  • 敏感字段一律 AES-256-GCM 加密落库，接口只回「是否已配置」，永不回传明文。
  • 生产环境里默认密码、默认 JWT 密钥、默认加密密钥没改，服务直接拒绝启动。
  • 登录限流：同一 IP 15 分钟最多 10 次；CORS 默认关闭，需要跨域得显式白名单。
  • 服务器 Agent 的命令黑名单是硬编码的：格式化、写块设备、关机、递归删根，开了 Agent 也一律拒绝。
  • Pino 日志对密钥字段做 redact，所有外部请求都带超时。

它现在跑在我的服务器上

技术栈很朴素：后端 Node.js + Fastify，数据库 SQLite（better-sqlite3，自带幂等迁移），定时任务 node-cron，管理后台 React + TypeScript + Vite + Tailwind；管理后台和 API 同进程挂载在同一个端口，不引入 Redis，缓存走内存加文件。部署支持 Docker / pm2 / systemd，我自己用的是 systemd：

cd /opt/PersonaBot
git pull --ff-only
pnpm install --frozen-lockfile
pnpm build
systemctl restart personabot

数据库备份用 SQLite 的 VACUUM INTO 做在线快照，不停机，默认留最近 10 份放在 data/backups/。测试用 node:test，覆盖时钟、上下文、记忆、提供商配置、会话清理、回复质量和限流，CI 在 push 和 PR 时跑 typecheck、test、build。

现在和边界

它现在只接 QQ 官方机器人 API v2，没有做微信、Discord 这些；主动消息、每日问候是在活跃时段按角色性格发起的，能调，但别指望它有真人那种分寸感。我个人的看法是：这类东西的价值不在「像人」，而在于记性好、脾气稳定、不会因为模型抽风就把上一句胡话当真。
