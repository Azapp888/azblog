AzLogin:让两个站点共用一套账号

我手上有 Azapp 和 AzKpop 两个站点,本来各自一套账号。问题很快就来了:我自己在两个站各注册一次,记两套密码;用户也一样,换个站就得重新注册。于是我做了 AzLogin——一个统一用户中心,让这两个站做到"一次注册,一号通行"。

它解决的核心问题

  • 统一账号:注册一次,Azapp / AzKpop 双站通用。
  • 统一登录 + 跨站会话共享(SSO):登录一次,就能带着会话在各站之间跳转。
  • 标准 OAuth 2.0 授权码模式:authorize / token / userinfo 三个端点,第三方站用 client_id + client_secret 接入。
  • JWT 双令牌:access token + refresh token,有效期都可配。
  • 邮箱验证码:基于 SMTP 的注册 / 找回验证。
  • 用户资料与头像:昵称、头像上传与修改。
  • 管理端:账号管理、OAuth 客户端(应用)管理、会话查看。

为什么用 OAuth 2.0 而不是简单共享 Cookie

一开始我想过最省事的做法:两个站读同一个 Cookie。但这在跨域、跨端的情况下很脆,而且会把手伸到别人域里。换成标准 OAuth 2.0 授权码模式之后,每个站就是一个"客户端",统一用户中心是"授权方",边界清清楚楚:谁要登录,就跳到这里授权,拿到 code 再换 token。以后要再接第三个站,也只是多注册一个客户端而已。

三套存储,按环境切

这是我在这个项目里最满意、也最费心的设计。同一套业务逻辑,做了三份存储实现:

  • MySQL:正式的服务器方案,入口是 server.js。
  • SQLite:单机、轻量部署,入口是 server-sqlite.js。
  • 纯 JSON 文件:零依赖,最快能跑起来,入口是 server-json.js。想先看看效果、或者只是本地玩玩,用它就够。

代码按 models/、routes/、models-sqlite/、routes-sqlite/ 这样分目录,切换存储只换启动入口,上层接口完全不变。代价是要维护三份实现,但换来的是"任何环境都能落地"。

怎么跑起来

npm install
cp .env.example .env        # 按需修改数据库、SMTP、JWT 配置

node server.js              # MySQL 版，默认 8001
# node server-sqlite.js     # SQLite 版
# node server-json.js       # JSON 版（零依赖，最快跑起来）

node server-frontend.js     # 前端页面，默认 3001

前端是原生 HTML5 / CSS3 / JavaScript,用 server-frontend.js 起静态服务并把 API 反向代理到后端。浏览器打开 http://localhost:3001 就是统一登录页。

安全上的几条底线

仓库里不含 .env(数据库密码、JWT 密钥、SMTP 授权码都在里面),也没有运行时数据、上传文件和测试账号,只保留 .env.example 模板。部署前必须自己生成强随机的 JWT_SECRET,并把 ADMIN_ACCOUNTS、允许互通的站点域名收紧。认证系统一旦出事就是大事,这几条没有妥协空间。
